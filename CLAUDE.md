# SWG3

Tools and research for Pokémon FireRed and LeafGreen (and Emerald, which shares the same base) running in Nintendo's GBA emulator on the Switch: every way of running code or changing the game state (box names, other text fields, glitches, controller input and the LDN trade channel). There is no access to ROM or RAM: everything goes through the controller or local wireless communication.

The contribution rules (setup, tests, parity, translations, content syntax, design system, dependencies, writing style, what cannot be accepted) apply here too: @CONTRIBUTING.md

## Principles

- Every feature that takes something into the game offers every path, each with step-by-step instructions: typing in the game (box names, Mail and other fields), the optional ESP32 board over local wireless, or just lookup and calculation when there is nothing to send.
- Site scope: RNG (static, wild including Tanoby Unown, eggs); pk3 viewer and validator (Switch game files only get a warning); community codes (decode, validate and guide the typing of names from the official generator; never create codes or reimplement the assembler); guides; save safety; Pokémon creator; put in your game (which eng10 codes to use, or a JSON recipe for the ESP32 host); edit and send back.
- Audience: community players, each on their own console and save. Pokémon-themed site with its own identity and no official logos; community sprites always credited (Credits page and `CREDITS.md`). Natural, direct tone.
- Everything works with manual controller input; automation tools are optional shortcuts and nothing is designed around them.

## Rules

- Keys (`prod.keys`, game key, LDN passphrase): never in docs, logs, captures, tests, error messages or commits. The only place in the project is `.secrets/` (ignored by git, permission 600), with the minimal file `.secrets/ldn.keys` from `swg3 keys minimize` (`docs/project/keys.md`). The full `prod.keys` never enters the project and is not changed. Never read or display key values. Only your own keys; for the game key and passphrase, reference the pokeldn files.
- `references/` holds third-party clones for study: never edit them and never run their code (exception: building `references/pokefirered` as the symbol source). Reimplement from understanding (`docs/architecture.md`).
- The name, `url` and `repo` come only from `src/swg3/brand.json`; never write them by hand.
- Never describe the production server or how the site is deployed in tracked files.
- Comments only for what the code does not say (decomp citations, non-obvious reasons, "not verified", notices of ported code). Mark unconfirmed technical facts "not verified" ("não verificado" in site text).
- Platform rights: Beater Studios (https://beaterstudios.com/, studiosbeater@gmail.com), in the footer, terms, privacy and `CREDITS.md`.
- Keep `docs/` and `docs/backlog.md` up to date as the work progresses; update this file when the scope or the rules change.

## Map

- `src/swg3/`: Python package. `gen3/` (pk3 and character formats, symbols, validation, species data, creator, ribbons, encounters, box names and keyboard, code plan, Base64 writer, word filter), `recipe.py` (ESP32 recipe, `docs/project/recipe.md`), `keys.py`, `cli.py` (`uv run swg3 --help`), `web.py` (reference of the site's services for parity). `data/` is generated by `tools/gen_*.py` from the decomp; never edit it by hand.
- `web/`: the site (React, TypeScript, Vite). The RNG exists only in TypeScript (`web/src/lib/gen3/`), with frozen vectors that are never regenerated. New routes go into `web/src/app/routes.ts`; a new kind of file fetched at runtime goes into the offline precache (`web/scripts/sw.mjs`); new UI pieces are born in `web/src/ui` and enter the `/design` catalog.
- Version: `version` in `web/package.json` and `pyproject.toml`, equal to the first entry of `web/src/content/changelog.ts` (tested); a release bumps both and adds the entry with highlights in Portuguese and English.
- `.github/`: the PR check runs typecheck, Vitest and Playwright for `web/` (Python is not on CI: run pytest locally); the ruleset (`.github/rulesets/main.json`) requires the jobs by name, so renaming one means updating the ruleset here and in GitHub.
- `docs/`: index in `docs/README.md`; tool specs in `project/`, technical research in `research/`, plus `architecture.md` and `backlog.md`.

## Game

- Target: English FireRed on the Switch, build revision 10, with symbols from the `firered_switch` target of `pret/pokefirered` (built in `references/pokefirered/`, sha1 checked against the Switch build; the `.map` is the address source).
- Entry point: the community's pre-E4 route (Mail glitch > species 0x0351 > grab ACE), with Switch adjustments (`docs/research/ace-box-names.md`); codes for the Switch in `docs/research/available-ace-codes.md`.
- Pokémon HOME arrives in October 2026, probably with a game update that may break codes. Never take Pokémon created or altered by ACE to HOME.
