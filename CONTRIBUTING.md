# Contributing to SWG3

Thanks for wanting to help. Issues and pull requests are welcome in English or Portuguese.

## Ways to help

- **Report a bug** in the site or the Python tools.
- **Report a result on the Switch.** Much of what the project knows about the Switch build is marked "not verified". If you ran a code, an RNG setup or a trade on your console, the "Result on the Switch" issue form is the most useful thing you can send.
- **Suggest a feature.** Every feature that takes something into the game should offer every possible path (typing in the game, the optional ESP32 board once it is ready, or just lookup), so say which ones your idea fits.
- **Send a pull request.** For anything bigger than a small fix, open an issue first so we can agree on the approach.

## Setup

Requirements: Python 3.11+ with [uv](https://docs.astral.sh/uv/) and Node.js 24 (`web/.nvmrc`).

```sh
uv sync --group dev
uv run --group dev pytest -q

cd web
npm ci
npm run dev
npm test
npx playwright install
npm run e2e
```

The repository layout and the documentation index are in the [README](README.md) and in [docs/README.md](docs/README.md).

## Rules for changes

- **Tests pass.** `uv run --group dev pytest -q`, `npm test` and `npm run e2e` in `web/`. New behavior comes with tests.
- **Parity.** Logic that exists in both Python (`src/swg3`) and TypeScript (`web/src/lib`) must give the same result. After changing it, run `uv run python tools/gen_parity_vectors.py` and `npm test`. The RNG exists only in TypeScript and its frozen vectors (`web/tests/vectors/frozen/`) are never regenerated.
- **Translations.** The site is in Portuguese and English. Interface text goes through `t("...")` with the Portuguese text as the key, and its English translation goes into `web/src/i18n/en/` (and `src/swg3/data/i18n_en.json` for Python). Errors that can reach the user also go through `t()`. The tests fail on untranslated text.
- **Decomp citations.** Every implemented format, address or game rule cites its origin in the decomp (file and function, from [pret/pokefirered](https://github.com/pret/pokefirered)). Anything not confirmed on the console is marked "not verified".
- **Generated data.** Files in `src/swg3/data/` are generated by `tools/gen_*.py`; never edit them by hand.
- **Design system.** Screens use the components in `web/src/ui`; a new piece is added there and to the catalog (`/design` in dev mode), which also has the design rules.
- **Name and addresses.** The site's name, domain and repository come only from `src/swg3/brand.json`; a test fails if they are written by hand.
- **Dependencies.** Versions are exact, and only releases at least 7 days old are accepted (`web/.npmrc`, `[tool.uv]` in `pyproject.toml`). Add a dependency only when it is really needed.
- **Code style.** Match the surrounding code. Code, comments and docs are in English; comments only where they add something the code does not say.
- **Writing.** In docs and interface text: no em or en dashes, no emoji, one paragraph per line (no hard wrap), and correct accents in Portuguese.

## Writing site content

Guides and text pages are Markdown in `web/src/content/`, one file per language (`pt/` and `en/`, same file names):

- A `key: value` header: `title`, `summary` (guides) or `lead` (pages), and for guides `slug`, `order`, `group`, `needs` and `level`.
- Blocks: `:::note`, `:::tip`, `:::warn` and `:::source`, closed by `:::`. `:::screen <name>` places a game screen component (`SCREENS` in `web/src/components/GuideBody.tsx`).
- Placeholders: `{{name}}` (site name), `{{repo}}` (repository URL), and `{{#analytics}}...{{/analytics}}` or `{{^analytics}}...{{/analytics}}` for text that depends on Analytics being on.
- Internal links without the language (`/rng`); English pages get `/en` on their own.
- The first occurrence of a glossary term (`web/src/content/glossary/`, same keys in both languages) becomes a tooltip.
- Professor Oak guides are in `web/src/content/tours/<lang>/<id>.md`: each step starts with `## <target>`, where the target is the element's `data-tour` mark (`-` for a centered step), optionally followed by `go=<action>` (run before the step) and `wait=<condition>` (to move on), both defined in `web/src/tours/registry.ts`.

A new page goes into the route registry (`web/src/app/routes.ts`). A new kind of file fetched at runtime must enter the offline precache (`OFFLINE` in `web/scripts/sw.mjs`).

## What cannot be accepted

- **Keys.** Never commit `prod.keys`, game keys, LDN passphrases or values derived from them, not even in tests, logs or screenshots. They belong only in `.secrets/`, which is ignored by git. See [docs/project/keys.md](docs/project/keys.md).
- **Code without a compatible license.** Code may be ported from AGPLv3 or GPLv3 projects, keeping their notices and recording the origin in [CREDITS.md](CREDITS.md). Projects without a license (for example CodeGenerator, EmeraldACE_web and EonTimer) can be studied and linked, but not copied.
- **Tools that act on other people's consoles** without their consent.
- **Official art or logos** beyond the game sprites the project already uses, which are credited.

## Out of scope for now

These are choices of the project, not rules: open an issue if you want to discuss one.

- **Generating new ACE codes.** The site checks and guides the community's published codes, which are already tested by many players; a new code can corrupt a save. It does not create codes or reimplement the code assembler.
