# SWG3

Tools and research for Pokémon FireRed and LeafGreen running in Nintendo's GBA emulator on the Switch, with Emerald in view since it shares the same base. This repository holds the source of the [SWG3 website](https://swg3.beaterstudios.com) (Switch Gen 3), its Python reference implementation, and the generators that extract game data from the decompilation. Support for an optional ESP32 radio board (trades and Mystery Gift without typing codes) is in development and not part of the repository yet.

The goal is to map and use every way of running code or changing game state on an unmodified console: box names and other text fields, glitches, controller input and the local wireless (LDN) trade channel.

## What the site does

- **RNG:** static, wild (including Tanoby Unown) and egg Pokémon, with a timer, seed checking from caught Pokémon and timer calibration. Everything runs in the browser.
- **Pokémon editor:** open, validate, create and edit pk3 files, with the game's own summary screen, region maps and encounter, move and breeding checks.
- **Community codes:** decode and check box names generated by the community ACE code generator, and type them with an on-screen copy of the game's naming keyboard.
- **Guides:** the route to ACE on Switch, available codes, save safety, and interactive guides with Professor Oak.

The site is in Portuguese and English.

## Safety

- Always save before running a code, and keep the boxes a code needs empty.
- Do not take Pokémon created or changed by ACE or by the editor to Pokémon HOME.
- Use these tools on your own console and save. Never send payloads to someone else's console without their consent.

## Repository layout

| Path | Contents |
|---|---|
| `web/` | The website (React, TypeScript, Vite), prerendered per page and language at build time |
| `src/swg3/` | Python package: pk3 format, validation, builder, box names, recipes and the reference for the site's logic |
| `tests/` | Python tests |
| `tools/` | Generators that extract data and art from the decompilation, plus parity vector generators |
| `docs/` | Project specs, research notes and backlog (start at `docs/README.md`) |

The site's game logic is checked against the Python implementation by parity tests: the Python side generates test vectors that the TypeScript tests must reproduce.

## Development

Requirements: Python 3.11+ with [uv](https://docs.astral.sh/uv/), Node.js 24 or newer (`web/.nvmrc`; with nvm, `nvm use` in `web/`).

```sh
# Python
uv run --group dev pytest -q
uv run swg3 --help

# Website
cd web
npm install
npm run dev          # development server
npm test             # Vitest
npx playwright install
npm run e2e          # Playwright, against the production build
npm run build        # typecheck and prerender into web/dist
```

After changing logic that exists on both sides, regenerate the parity vectors with `uv run python tools/gen_parity_vectors.py` and run `npm test` in `web/`.

Game data in `src/swg3/data/` is generated, never edited by hand. The generators in `tools/` read the [pret/pokefirered](https://github.com/pret/pokefirered) decompilation (built locally to obtain symbols) and other references, which are not part of this repository; see each script's header for its sources.

Keys for the LDN work (`prod.keys` and derived files) must never be committed: they belong in `.secrets/`, which is ignored by git (see `docs/project/keys.md`).
