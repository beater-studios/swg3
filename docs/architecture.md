# Suite architecture

Stack: Python 3.11+ (`uv`), `swg3` package in `src/`. AGPLv3 license.

## Principles

- One suite, instead of loose scripts per game and per function.
- References (`references/`) are study material. Reimplement from understanding, with our own tests.
- FRLG addresses come from the `.map` of the compiled decomp (`references/pokefirered/pokefirered_switch.map`), generated by script, never copied by hand.
- Every layer is testable offline, without a console: recorded captures and an emulator.
- Keys never inside the repository.

## Layers

| layer | responsibility | study reference |
|---|---|---|
| firmware (in development) | ESP32 as a radio: LDN and Ethernet frames over serial | `pokeldn/firmware/esp32`, `docs/hardware_esp32.md` |
| radio (in development) | serial driver, frame protocol, counters | `pokeldn/ldn/esp32_wlan` |
| ldn | advertisement, authentication, keys, host and station | `vendor/LDN`, `docs/ldn.md` |
| pia | session, encryption, Reliable | `pokeldn/ldn`, `docs/pia.md` |
| gba-link | emulated RFU, link commands, barriers | `pokeldn/gba`, `docs/frlg_link.md` |
| games | trade, Mystery Gift, Union Room in FR/LG | `pokeldn/frlg` |
| formats | pk3/ek3, Wonder Card | decomp, pokeldn |
| payloads | ARM code for FRLG, assembled and emulated before sending | `pokeldn/asm`, decomp |
| ace | box name generation, hexwriter, code catalog | CodeGenerator, EmeraldACE_web |
| rng | LCRNG, seeds, target search. Only in TypeScript, on the site (`web/src/lib/gen3/`) | ten-lines, PokeFinder |
| interfaces | single CLI, static site (`web/`, React + TypeScript, TS logic checked against Python), later a trade room | `web/` |

## Radio board (in development)

The trade path uses a classic ESP32 as the radio, with the logic on the PC, as pokeldn does. The firmware and the serial protocol with the PC are being developed outside this repository and come back when they are tested on the board.

## Suggested order

1. Formats and addresses: pk3, character table and `firered_switch` symbols. Done (`src/swg3/gen3/`) and checked against 1,463 real PKHeX files and the `rawpk.txt`. Only a Pokémon taken from the target console is missing, which depends on the trade host.
2. Firmware and radio: first contact with the console, listening only. In development outside this repository: the firmware builds; the hardware test and the PC program that talks to the board are missing. Next step.
3. LDN and Pia: join a session.
4. FRLG trade as host.
5. Mystery Gift and payloads: save dump (read only), then hooks. A save reader can be tested earlier with the 3 real saves in `pk3-jp/`.
6. Other games (Emerald first, because of the shared base) and web room.

The full list of what is left, including what depends on console testing, is in the [backlog](backlog.md).
